# 벌금 원인 분석과 모델 개선 정리 (2026-10-28)

평가 기간(2024-06~2025-05) 벌금을 **2억 130만 원 → 1억 9,650만 원(−2.4%)** 으로 줄이는 변경 두 가지를 찾았습니다.

1. MLP는 여러 에폭의 예측을 평균합니다.
2. GBDT에는 "예보가 전날 10시와 17시 사이에 얼마나 바뀌었는지"를 입력으로 추가합니다.

두 변경은 `ugi/penalty-analysis-2026-10-28` 브랜치 코드에 반영했습니다. 반영한 코드로 다시 돌려 같은 벌금(1억 9,650만 원)이 나오는 것까지 확인했습니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 평가 기간 (홀드아웃) | 2024-06~2025-05. 학습에 전혀 쓰지 않고 성적 확인에만 쓰는 1년 |
| 벌금 | 대회 점수식의 감점 항. 0.1 × SMP × k × \|팀 합계 예측 − 팀 합계 실적\|. 11~15시는 k=3, 그 외 k=1 |
| 라운드 10 / 17 | 전날 10시 / 17시에 발행된 날씨 예보. 둘 다 예측 마감(전날 17시) 전이라 사용 가능 |
| 실측 날씨 | 실제로 관측된 날씨. 학습 기간에만 있고 대회 평가 기간에는 없음. 비교 실험용 |
| 시드 | 학습의 무작위성을 정하는 번호. 시드만 바꿔도 결과가 조금씩 달라짐 |
| 에폭 | 학습 데이터를 한 바퀴 다 보는 단위 |

## 출발점: 기존 모델

- **입력 24개:** 두 예보 회사의 라운드 17 날씨, 태양 위치, 날짜, 설비용량, 위경도
- **정답:** 이용률(발전량 ÷ 설비용량)
- **MLP:** 은닉층 512-512-256과 발전소 임베딩. 검증 기간(2024-04~05) MAE가 가장 낮은 에폭 하나를 골라 씀. 시드 3개 평균
- **GBDT:** LightGBM, 손실은 L1. 시드 3개 평균
- **제출 방식:** MLP 0.7 + GBDT 0.3 혼합
- **채점:** 이번에 대회 점수식으로 벌금을 계산하는 도구를 만들었습니다([mlp/eval_penalty.py](../mlp/eval_penalty.py)). MAE는 발전소 하나하나의 오차라서, 팀 합계로 매기는 벌금과 순위가 다를 수 있기 때문입니다.

| 기존 모델 (평가 기간) | 벌금 |
|---|---|
| 주최 측 베이스라인 (L2, 라운드 10·17 평균) | 2억 3,020만 원 |
| GBDT 단독 (시드 3개) | 2억 1,710만 원 |
| MLP 단독 (시드 3개) | 2억 450만 원 |
| **혼합 0.7/0.3 (기준)** | **2억 130만 원** |

### 5번 보충: 라운드 변화가 하는 일

라운드 변화 입력을 넣은 GBDT는 **"바뀐 예보를 다 믿지는 않는다"** 는 패턴을 스스로 배웠습니다.

| 10시 → 17시 구름 예보 변화 | 비중 | 기존 모델 편향 | 추가 후 편향 |
|---|---|---|---|
| 많이 맑아짐 | 3% | +2.6% | −1.2% |
| 거의 그대로 | 74% | +1.1% | +1.0% |
| 많이 흐려짐 | 3% | −6.0% | −0.5% |

예보가 바뀌었을 때 실제 날씨는 두 예보의 중간쯤인 경우가 많았습니다. 다만 예보가 바뀐 시간대가 전체의 26%뿐이라, 전체 효과는 1% 정도입니다.

## 주의할 점

- **같은 평가 기간을 보면서 방법을 골랐습니다.** 그래서 실제 효과는 이 숫자보다 작을 수 있습니다. 다만 "16에폭 전부 평균"은 세부 조정 없이 정한 단순한 규칙이라, 그 위험은 작다고 봅니다.
- **평가 기간이 1년 하나뿐입니다.**
- **MLP는 같은 설정으로 다시 돌려도 결과가 조금 다릅니다.** 멀티스레드 연산 때문이며, 에폭 평균을 쓰면 이 영향도 줄어듭니다.
- **예보 탓 몫 31%는 모델로 고칠 수 없습니다.** 실측 날씨를 넣어도 벌금 1억 5,240만 원이 남습니다. 그중 얼마가 "원래 알 수 없는 부분"이고 얼마가 "모델이 더 배울 수 있는 부분"인지는 아직 나누지 못했습니다.
- 실측 날씨 실험은 비교용이며, 실측 날씨는 제출 모델에 쓰지 않습니다.
